## 슬라이드 2 — 프로젝트 소개

### Travelries란?

> 여행 사진을 올리면 **GPS 위치를 자동 추출**하고,  
> **얼굴을 인식**해서 누구와 어디를 다녔는지 한눈에 볼 수 있는 웹앱입니다.

**탄생 배경**
- 여행 사진이 쌓일수록 "이게 어디서 찍은 거지?" "이 날 누구랑 있었지?" 찾기가 어려움
- 사진 앱은 많지만 **지도 + 얼굴인식 + 통계**를 한 곳에 모은 서비스는 없음
- 직접 만들어보자 → Travelries

## 슬라이드 4 — 사용 방법 (데모 흐름)

### Step 1 — 회원가입 / 로그인
- `/signup` 에서 이메일 + 비밀번호로 가입
- 로그인 후 홈 화면 이동

### Step 2 — 사진 업로드
1. 홈 화면 드래그&드롭 또는 클릭
2. **단일**: 사진 1장 선택 → 자동 분석 (EXIF · GPS · 얼굴 인식)
   - 파일명 변경 가능 → **Save to Map** 클릭
3. **배치**: 여러 장 선택 → 진행률 표시 → 완료 후 카드별 리뷰 + 이름 변경

### Step 3 — 지도에서 확인
- **Map** 탭 → 저장된 사진들이 위치별 마커로 표시
- 마커 클릭 → 썸네일 팝업

### Step 4 — 앨범 탐색
- **Albums** 탭 → Monthly / Trips 뷰 전환
- **Trips**: 날짜 + GPS 기준으로 같은 여행 자동 묶음
- 상단 검색창 · 날짜 필터 사용 가능

### Step 5 — 얼굴 인식
- **Faces** 탭 → 사진 속 얼굴들을 같은 사람끼리 자동 클러스터링
- 인물 카드의 **"See in Albums"** → 그 사람이 찍힌 사진만 필터링

### Step 6 — 통계
- **Stats** 탭 → 월별 업로드, 방문 장소, 인물/풍경 비율 시각화

### Step 7 — 협업 앨범
- **Collab** 탭 → 새 앨범 생성 → 초대코드 공유
- 친구가 `/collab/join?code=XXXX` 로 참여

### Step 8 — 사진 공유
- Albums 또는 Saved에서 사진 클릭 → Share 버튼
- 생성된 공개 URL 복사 → 누구에게나 전송 가능 (비로그인 OK)

## 슬라이드 5 — 핵심 기술 상세

### 1. EXIF + GPS 자동 추출
```
사진 업로드
    ↓
exifr 라이브러리로 EXIF 데이터 파싱
    ↓
GPS 좌표 추출 (위도/경도)
    ↓
OpenStreetMap Nominatim API → 주소 변환
    ↓
지도 마커 + 앨범 위치 태그 자동 설정
```
- GPS 없는 사진 → 직접 위치 검색 or 현재 위치 사용

### 2. 브라우저 얼굴 인식 (face-api.js)
```
사진 업로드
    ↓
face-api.js SSD MobileNetV1 모델 (브라우저 내 실행)
    ↓
얼굴 위치 박스 + 128차원 특징 벡터 추출
    ↓
localStorage에 저장
    ↓
Faces 페이지: 유클리드 거리로 같은 사람 클러스터링
```
- 서버 없이 **100% 클라이언트 사이드** 처리 → 개인정보 보호

### 3. Trips 자동 분류 알고리즘
```
전체 사진
    ↓
날짜 gap 3일 이상 → 다른 여행으로 분리
    ↓
같은 날짜 그룹 내에서 Haversine 거리 계산
    ↓
1.5km 반경 내 사진 → 같은 장소 카드로 묶음
    ↓
결과: "속초 카페" "속초 해변" 처럼 장소별 카드 생성
```

### 4. Supabase Storage (개인 사진)
```
사진 업로드 완료
    ↓
base64 → Blob 변환
    ↓
Supabase Storage "user-photos" 버킷에 업로드
    ↓
Public URL 저장 (localStorage의 imageUrl 필드)
    ↓
실패 시 base64 그대로 fallback
```
- 기존 5MB localStorage 한계 극복

## 슬라이드 10 — 배운 것들

### 이번 프로젝트에서 배운 핵심 내용

#### 프론트엔드
- **Next.js 14 App Router**: `"use client"` / `"use server"` 분리, layout/template 구조, 동적 라우팅(`/collab/[id]`)
- **TypeScript**: 타입 정의로 버그를 컴파일 시점에 잡는 경험
- **Tailwind CSS**: 유틸리티 클래스로 빠른 UI 구현
- **framer-motion**: 선언형 애니메이션

#### AI / 알고리즘
- **face-api.js**: 브라우저에서 AI 모델 로드·실행하는 방법
- **DBSCAN / 유클리드 거리**: 얼굴 클러스터링 알고리즘
- **Haversine 공식**: 위도·경도 두 점 사이 실제 거리 계산
- **EXIF 파싱**: 사진 메타데이터 구조 (GPS, 날짜, 카메라 정보)

#### 백엔드 / 인프라
- **Supabase**: Auth / DB / Storage / Realtime 통합 사용법
- **Row Level Security (RLS)**: 사용자별 데이터 접근 제어
- **Supabase Storage**: base64 → Blob 변환, 버킷 정책 설정
- **Realtime**: postgres_changes 채널로 실시간 이벤트 수신

#### 개발 프로세스
- **Git / GitHub**: 브랜치, 커밋 메시지 컨벤션
- **Vercel**: GitHub 연동 자동 배포 파이프라인
- **ESLint + TypeScript**: 코드 품질 관리
- **PWA**: manifest.json, 아이콘, 오프라인 지원 개념

## 슬라이드 13 — Q&A

### 예상 질문 & 답변

**Q. 얼굴 인식이 틀릴 수도 있지 않나요?**
A. 네, 브라우저 모델 특성상 조명이 어둡거나 측면 얼굴은 인식률이 떨어집니다. 방학 중 서버 기반 고정밀 모델(InsightFace)을 연결할 예정입니다.

**Q. 사진 개인정보는 안전한가요?**
A. 얼굴 인식은 100% 브라우저 내에서 처리되고, 얼굴 이미지 자체는 서버로 전송되지 않습니다. 사진 원본은 본인만 접근 가능한 Supabase Storage에 저장됩니다.

**Q. 여러 기기에서 같은 사진을 볼 수 있나요?**
A. 현재는 이미지 파일은 Supabase Storage에 저장되어 공유되지만, 사진 목록(메타데이터)은 아직 기기별 localStorage에 있어 동기화가 안 됩니다. 방학 중 DB 마이그레이션으로 해결할 예정입니다.

**Q. GPS가 없는 사진은 어떻게 되나요?**
A. 업로드 시 "현재 위치 사용" 버튼이나 직접 장소 검색으로 수동 위치 지정이 가능합니다.

**Q. 무료로 운영할 수 있나요?**
A. 현재 Vercel 무료 플랜 + Supabase 무료 플랜으로 운영 중입니다. 사용자가 늘면 유료 전환이 필요할 수 있습니다.

## 발표 스크립트

---

### [슬라이드 1 — 표지]

안녕하세요, 저희 팀은 여행 사진 관리 웹앱 **Travelries**를 발표하겠습니다.

Travelries는 여행 사진을 올리면 GPS 위치를 자동으로 추출하고, AI로 얼굴을 인식해서 누구와 어디를 다녔는지 한눈에 볼 수 있는 서비스입니다.

---

### [슬라이드 2 — 프로젝트 소개]

이 프로젝트를 시작하게 된 계기는 간단합니다. 여행을 다녀오면 사진이 수백 장씩 쌓이는데, "이게 어디서 찍은 거지?", "이 날 누구랑 있었지?" 하는 순간이 생각보다 많습니다.

기존 사진 앱들도 있지만, **지도 + 얼굴 인식 + 통계**를 한 곳에서 제공하는 서비스는 없었습니다. 그래서 직접 만들어보기로 했습니다.

---

### [슬라이드 3 — 전체 기능 구조]

전체 기능은 크게 8개 영역으로 나눌 수 있습니다.

사진 업로드, 지도, 앨범, 얼굴 인식, 통계, 협업 앨범, 공유, 그리고 실시간 알림입니다.

각 기능이 독립적으로 작동하면서도 서로 연결되어 있습니다. 예를 들어 Faces 페이지에서 특정 인물을 클릭하면 Albums 페이지에서 그 사람이 찍힌 사진만 필터링해서 볼 수 있습니다.

---

### [슬라이드 4 — 사용 방법 데모]

실제로 어떻게 사용하는지 보여드리겠습니다.

먼저 회원가입 후 로그인합니다. 홈 화면에서 사진을 드래그&드롭하거나 클릭해서 올리면, 자동으로 EXIF 데이터에서 GPS 위치와 촬영 날짜를 읽어옵니다.

동시에 AI가 사진에서 얼굴을 감지합니다. Save to Map 버튼을 누르면 지도에 저장됩니다.

여러 장을 한 번에 올릴 수도 있습니다. 배치 업로드 모드에서는 진행 상황을 실시간으로 보여주고, 완료 후에 각 사진의 이름을 수정할 수 있습니다.

---

### [슬라이드 5 — 핵심 기술 상세]

기술적으로 가장 흥미로운 부분 세 가지를 소개합니다.

첫째, **얼굴 인식**은 서버 없이 브라우저에서만 처리합니다. face-api.js 라이브러리를 사용해서 사진에서 128차원 특징 벡터를 추출하고, 유클리드 거리로 비슷한 얼굴끼리 묶습니다. 얼굴 이미지가 서버로 전송되지 않아 개인정보 보호에 유리합니다.

둘째, **Trips 자동 분류**는 날짜 gap과 Haversine 거리 공식을 함께 씁니다. 날짜가 3일 이상 비면 다른 여행으로 분리하고, 같은 날짜 내에서도 1.5km 이상 떨어지면 다른 장소 카드로 구분합니다. 속초 카페, 속초 해변처럼 장소별로 자동 분류됩니다.

셋째, **Supabase Storage** 연동으로 기존 localStorage 5MB 한계를 해결했습니다. 사진을 Blob으로 변환해서 클라우드에 저장하고, URL만 localStorage에 보관합니다.

---

### [슬라이드 8 — 개발 완료 목록]

이번 학기 동안 완성한 기능들을 정리했습니다.

사진 업로드, 지도, 앨범, 얼굴 인식, 통계, 협업 앨범, 공유 링크, 실시간 알림, Supabase Storage 연동, PWA 지원까지 완료했습니다.

전체적으로 핵심 기능의 약 80%를 완성했다고 볼 수 있습니다.

---

### [슬라이드 9 — 현재 제한사항]

솔직하게 말씀드리면 아직 해결이 안 된 부분도 있습니다.

가장 중요한 것은 **멀티디바이스 동기화**입니다. 현재 사진 목록이 기기 로컬에 저장되어 있어서, 노트북에서 올린 사진이 핸드폰에서 보이지 않습니다. 이건 방학 중 DB 마이그레이션으로 해결할 예정입니다.

---

### [슬라이드 10 — 배운 것들]

이번 프로젝트에서 가장 많이 배운 것은 **풀스택 개발의 흐름**입니다.

Next.js로 프론트엔드를 만들고, Supabase로 인증과 데이터베이스와 파일 저장을 모두 처리했습니다. AI 모델을 브라우저에 직접 올리는 것, GPS 좌표로 거리를 계산하는 알고리즘, 실시간 알림을 WebSocket으로 받는 것 등 다양한 기술을 실제 서비스에 적용해봤습니다.

특히 에러를 마주치고 디버깅하는 과정에서 가장 많이 성장했습니다.

---

### [슬라이드 11 — 향후 계획]

방학 동안은 주로 안정화에 집중할 예정입니다. 멀티디바이스 동기화, 이메일 인증, 협업 댓글 기능을 완성하겠습니다.

다음 학기에는 소셜 기능을 강화해서 팔로우/팔로워, 여행 스토리 공유 기능을 추가할 계획입니다. 그리고 AI를 더 고도화해서 자동 사진 분류와 하이라이트 생성 기능도 넣고 싶습니다.

---

### [슬라이드 12 — 최종 목표]

Travelries의 궁극적인 목표는 **"여행 기록 SNS"**입니다.

지금은 개인 기록 앱에 가깝지만, 장기적으로는 여행자들이 서로의 루트를 공유하고, "이 카페 좋아요!", "이 해변 제가 다녀왔어요!" 같은 인터랙션이 가능한 플랫폼으로 발전시키고 싶습니다.
